# ADR-005 · 代码签名证书降级为非阻塞项

| 项 | 内容 |
|---|---|
| 状态 | **已采纳**（2026-11-11） |
| 影响范围 | PRD §10 风险 R2、§12 前置条件 B2、§12.1 全文 |
| 关联 | [ADR-002](ADR-002-l2-http-默认开启与单包.md)（单文件分发路径决定了本 ADR 的结论） |

## 背景

一个未签名的 exe 分发出去，接收方第一次运行时 Windows 可能弹出「Windows 已保护你的电脑」。早期版本把「采购代码签名证书」列为 M0 的**阻塞前置条件**——没有证书，分发就是断的。

## 核实到的机制

把这件事讲清楚，需要区分两样东西：

| 提示 | 触发机制 | 自签名证书能消除吗 |
|---|---|---|
| 「未知发布者」 | UAC / `CreateProcess` 的签名校验缺失 | ✅ 能（需把根证书导入受信任存储） |
| 「Windows 已保护你的电脑」 | **SmartScreen** | ❌ 不能 |

SmartScreen 的真正判据是 **Mark of the Web（MOTW）**：文件被写入时在 NTFS 备用数据流 `Zone.Identifier` 里打的标记（`[ZoneTransfer]` / `ZoneId=3` / `HostUrl=...`）。它由**浏览器下载、邮件附件**打上。而：

- **U 盘拷贝、局域网共享盘、由别的程序 `File.Copy` 生成 → 不带 MOTW → 不弹窗。**
- FAT32 / exFAT 无法承载备用数据流，拷到这类分区上标记就消失了。

SmartScreen 评估两个信号：**发布者声誉 + 文件哈希声誉**。这意味着：

- 新签名二进制**在声誉累积起来之前照样会弹**——签名不是开关，是起点。
- 未签名文件每个版本从零开始累积，声誉**不能跨版本转移**；同一发布者身份签名后才能延续。
- OV / EV 证书首次下载同样告警；**EV 证书早已不再绕过 SmartScreen**（早年有效，现已失效，网上大量过时资料仍这么说）。

## 决定

**代码签名降级为「可选、不阻塞发版」的项目**，并在 PRD 里新增 §12.1 用五档对策替代原来的单点要求：

| 档 | 做法 | 成本 | 效果 |
|---|---|---|---|
| 0 | 改分发路径：U 盘 / 共享盘 / 由可信程序释放到本地 | 0 | **完全绕开**，零提示 |
| 1 | 发布 SHA-256 + 说明「右键 → 属性 → 解除锁定」 | 0 | 消除 MOTW 后的残留拦截 |
| 2 | 自签名证书（`New-SelfSignedCertificate` + `signtool`） | 0 | 消 UAC 提示；内网可 GPO 推根证书；**对公网 SmartScreen 无效** |
| 3 | OV 证书 | 约 200–500 美元/年 + 硬件 token | 有身份，但仍需累积声誉 |
| 4 | Azure Trusted Signing（原 Artifact Signing） | 约 10 美元/月 | 需 3 年营业历史（个人可申请）；中国大陆主体可用性需实测 |
| 5 | Microsoft Store 上架 | — | 与 P3「绿色单 exe」冲突，不采用 |

落在 FerroOCR 上的具体结论：

1. **开发期完全不需要证书**，不阻塞任何里程碑。
2. 面向熟人或内部小范围分发 → 走**档 0**，这条路上零成本零提示。
3. 同时做**档 1**（发布页给 SHA-256 与解除锁定说明），几乎零成本。
4. 有企业客户要求显式发布者身份时再做**档 2**。
5. **只有当需要让陌生用户从公网直接下载 exe 时**，才必须认真处理签名，此时评估档 3 / 4。

## 后果

- R2 的影响等级从「阻塞」降为「中（仅限从网络下载这条分发路径）」。
- PRD §12 前置条件 B2 标记为已降级，M0 不再等待证书采购。
- 这条决策之所以成立，很大程度依赖 [ADR-002](ADR-002-l2-http-默认开启与单包.md) 的单文件形态——单 exe 走 U 盘/共享盘是最自然的分发方式。若日后改成安装包分发，MOTW 与信誉问题的权重会重新上升。

## 教训

**「要发 exe 就得买证书」这个结论，是把两个不同的机制（UAC 签名校验、SmartScreen 信誉评估）混成了一个。** 把事情拆到机制层面之后，会发现大部分真实分发场景根本不在受影响的那条路径上——先问「谁、通过什么渠道拿到文件」，再决定要不要花钱。
