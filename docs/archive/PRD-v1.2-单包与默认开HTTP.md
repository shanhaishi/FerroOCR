# 存档 · PRD v1.2（单包 + 启动参数 + L2 默认开启）

> **状态**：已被 **v1.3** 取代（2026-11-11）。当前版本见 [../PRD-FerroOCR.md](../PRD-FerroOCR.md)。
>
> v1.2 是原地改写成 v1.3 的，没有保留完整快照。以下是 v1.2 相对 v1.1 的实质变化，以及 v1.3 在它基础上又做了什么。

## 1. v1.2 修正了 v1.1 的两个判断题

### 1.1 「L2 HTTP 默认关」→「默认开」

v1.1 把 L2 定为默认关闭，理由是「不暴露网络」。

用户（m01035）的经验反驳：**「市面上的一些类似的工具，都会选择优先用 HTTP 来进行交互」**，并明确要求默认开。

v1.2 采纳。补强的论证：

- 端口**只绑 `127.0.0.1`** 时，「不暴露网络」这条理由根本不成立；
- 默认关会逼着每个调用方学会传 `--http`——**而老工具的用户不会传参数**；
- 默认开 + 一道回环限制，比默认关 + 要求每个调用方都会传参更接近 P1（附属工具）。
- 想关的人加 `--no-http`；`--bind` 传非回环值直接拒绝启动。

### 1.2 「出两个包」→「只出一个包 + 启动参数」

v1.1 的 Q10 建议出两个二进制来绕开默认值争议：`ferroocr.exe`（默认关 HTTP）与 `ferroocr-tool.exe`（默认开 L2，专供老工具）。

用户（m01035）否掉：**「最好保持一个包，这样构建和分发管理都轻松」**，并提出**用启动参数开关功能**——「这好像也是比较常见的做法？」

v1.2 采纳。落地方式：

| 项 | v1.2 的做法 |
|---|---|
| 发行物 | 唯一 `ferroocr.exe`，CPU 引擎 + GPU 引擎（ORT+DirectML）+ 模型全在内，≤60 MB |
| ORT dylib | `onnxruntime.dll` + `DirectML.dll` 内嵌，**首次用 GPU 时**才释放到 `%LOCALAPPDATA%\FerroOCR\runtime\<ver>\`，SHA-256 校验 |
| 默认姿态 | 无参数 = 常驻 + L2 开 + L3 开 |
| 参数表 | 新增 §5.2.1：`--no-http` / `--http` / `--port` / `--bind` / `--pipe` / `--idle` / `--device auto\|cpu\|gpu` / `--pool` / `--max-ram` / `--log` / `--wait` / `--once` / `--selftest` / `--version` / `--help` |
| 优先级 | 命令行 > 环境变量 > `endpoint.json` > 内置默认 |
| 逃生口 | `FERRO_ARGS` 环境变量，SDK 拉起时原样附加——**调用方改不了代码也能统一改服务行为** |
| 自省 | `--help` 与 `GET /info` 必须回显**生效值 + 来源** |

## 2. v1.2 还收紧了 SDK 范围

v1.1 规划五套 SDK（Python / C# / Node / Go / Rust，约 2.5 人周）。用户确认的语言清单是 **按键精灵 / 易语言 / Python / aardio**。

v1.2 改为：

- **Python = 唯一 P0 SDK**（1 周）；
- **C# = P1**，跟进；
- **Node / Go / Rust = P2**，不列入首发；
- **按键精灵 / 易语言 / aardio 不写 SDK**——它们本来就有 HTTP 对象（`MSXML2.XMLHTTP` / `WinHttp.WinHttpRequest.5.1` / `inet.http`），各给 4–5 行可复制片段。

## 3. v1.3 在 v1.2 基础上又改了什么

| 议题 | v1.2 | v1.3 |
|---|---|---|
| 代码签名 | R2 / B2 列为**阻塞项** | **非阻塞**。新增 §12.1 解释：只有带 Mark of the Web（浏览器/邮件下载）的文件才触发 SmartScreen；U 盘、共享盘、由其他程序释放的 exe 不带标记，不弹窗。附 5 档对策与成本 |
| 单包体积 | 目标 ≤60 MB，未拍板 | **已确认接受 60 MB**（用户：无奈接受，暂无更小方案） |
| 截屏识别 | Q11 待定 | **明确不做**（新增非目标 N11）：只接受调用方传入的图片 |
| 未决问题 | 11 条 | **8 条** |

## 4. 沿用下来的设计（v1.3 未改）

四级接入阶梯（L2 ⭐ 默认开 / L0 一次性 / L1 文件 / L3 管道）、四级 JSON 结构完全一致、路径直传不走 base64、模型 `include_bytes!` 内置、无 tokio、仅 Windows、`opt-level=3`+LTO+strip、空闲自退出、命名互斥量单实例。
