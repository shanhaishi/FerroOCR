# 存档 · PRD v1.1（四级接入阶梯）

> **状态**：已被 **v1.2** 取代（2026-11-11）。当前版本见 [../PRD-FerroOCR.md](../PRD-FerroOCR.md)。
>
> 本文档记录 v1.1 的核心设计、它为什么被改，以及哪些部分原样保留到了 v1.2。
> v1.1 的正文是原地改写为 v1.2 的，没有独立快照；以下是改动前的设计摘要。

---

## 1. v1.1 想解决什么

v1.0 把 **Named Pipe 定为唯一传输通道**，理由是"无端口、无防火墙弹窗、无网络暴露"。

用户（m00852）指出：要接入的语言里包含**按键精灵**这类技术栈很老的脚本工具。核实结论：

- 按键精灵调 DLL 需要把插件放进其 `plugin` 目录并**重启软件**才能识别 → 等于要求用户额外安装，违反 P1；
- 按键精灵的 `Declare Function` 只能声明 `GetAsyncKeyState` 这类简单签名，**做不到**带 `OVERLAPPED` / `SECURITY_ATTRIBUTES` 结构的管道客户端；
- 按键精灵实际调 OCR 的通行做法是 `CreateObject("MSXML2.XMLHTTP")` 发 POST，或 `RunApp` 跑命令 + `openTextFile` 读结果文件。

→ **v1.1 引入「四级接入阶梯」**，把传输方式从"我选一种"改为"按调用方能力分四级"。

## 2. v1.1 的四级阶梯

| 级别 | 方式 | 延迟 | 需常驻 | v1.1 的默认状态 |
|---|---|---|---|---|
| L0 | `ferroocr.exe ocr --image a.png --out r.json` | ~1–2 s | ❌ | 可用 |
| L1 | 命令 + 文件（`--in req.json --out res.json`） | ~1–2 s | ❌ | 可用 |
| L2 | 本地 HTTP `127.0.0.1:1224` | ~5–15 ms | ✅ | **默认关闭，需 `--http`** |
| L3 | Named Pipe `\\.\pipe\ferroocr-v1` | ~1–3 ms | ✅ | SDK 默认 |

配套设计（这些在 v1.2 中全部保留）：

- **四级 JSON 结构完全一致**（同一 schema、同一错误码），换级不改业务代码；
- SDK 按 **L3 → L2 → L0** 自动降级；
- 路径直传，不走 base64（服务端直接读文件）；
- `--port` 可固定端口，实际端口写入 `endpoint.json` 供调用方读取。

## 3. v1.1 另外两个建议，都被用户否掉了

### 3.1 L2 默认关闭

v1.1 的理由是"安全"：默认不开端口，就不会有网络暴露面。

**用户经验反驳（m01035）**：「市面上的一些类似的工具，都会选择优先用 HTTP 来进行交互」，并明确要求**默认开启**。

v1.2 采纳。补强的理由：端口**只绑 127.0.0.1**，此时"不暴露网络"这条理由并不成立；而默认关会逼着每个调用方学会传 `--http`——**老工具的用户不会传参数**。默认开 + 一道回环限制，比默认关 + 要求每个调用方都会传参更接近 P1。想关的人加 `--no-http`。

### 3.2 两个包（`ferroocr.exe` 默认关 / `ferroocr-tool.exe` 默认开）

v1.1 的 Q10 建议出两个二进制，用"专门给老工具的那个"绕开默认开关的争议。

**用户否掉（m01035）**：「最好保持一个包，这样构建和分发管理都轻松」，并提出**用启动参数开关功能**——「这好像也是比较常见的做法？」

v1.2 采纳：**只有一个 `ferroocr.exe`**，默认姿态即全功能（常驻 + HTTP 开 + 管道开），要改行为就传参数（§5.2.1 参数表）；调用方不方便改命令行时可用 `FERRO_ARGS` 环境变量。

## 4. v1.1 还有一个错误：SDK 铺得太开

v1.1 规划了**五套 SDK**（Python / C# / Node / Go / Rust），合计 2.5 人周。

用户确认的开发语言清单是：**按键精灵 / 易语言 / Python / aardio**（前两者自己几乎不用，但会分发出去给别人用）。

v1.2 收紧为：

- **Python = 唯一 P0 SDK**（1 周）；
- **C# = P1**，跟进；
- **Node / Go / Rust = P2**，不列入首发，在此之前直接用 L2 HTTP 或 L0；
- **按键精灵 / 易语言 / aardio 一律不写 SDK**，改用系统自带 HTTP 对象（`MSXML2.XMLHTTP` / `WinHttp.WinHttpRequest.5.1` / `inet.http`），各给 4–5 行可复制片段。

理由：给冷门语言维护 SDK 是无底洞，而这些语言**本来就有 HTTP 能力**——给它们的正确交付物是文档片段，不是包。

## 5. 三条教训（v1.0 → v1.1 → v1.2 累计）

1. **「调用方支持什么」必须先问清，再定传输层。** 先选技术再假设调用方能适配，一定会返工。最弱调用方决定下限。
2. **标成「可选 / 默认关闭」的功能，如果只有"不方便的人"才用，它就是必需品。** 默认值本身就是产品决策，不是配置项。
3. **对附属工具而言，可达性优先于优雅。** 端口、防火墙弹窗、"不够干净"——这些都是设计者的洁癖，不是用户的成本。
